# data/

This directory is where you place INPUT data. Nothing here is private and no
real-world dataset ships with the project -- only a small synthetic example so the
quickstart runs out of the box. Bring your own data and point the tool at it.

## Layout

```text
data/
+-- <name>/
    +-- orig/        <- your original source files (tracked if you choose to commit them)
    +-- prepared/    <- intermediate prepared artifacts (gitignored -- regenerable)
```

The directory name is just an organizing convention. The CLI never reads this tree
directly: you pass a source path explicitly, and prepared datasets are persisted
under the configured state directory (see the top-level `README.md`).

## Bring your own data

1. Drop a `.csv` or `.parquet` file anywhere (a natural home is `data/<name>/orig/`).
2. Tell the tool which columns it must carry, as floats, via configuration --
   `Settings.required_columns`. Either set an environment variable:

   ```bash
   set -x GRAVITYML__REQUIRED_COLUMNS '["feature_a", "feature_b", "target"]'
   ```

   (`set -x` is fish; use `export` in bash/zsh) or add it to a `gravityml.toml` in
   the project root:

   ```toml
   required_columns = ["feature_a", "feature_b", "target"]
   ```

3. Prepare it: `uv run gravityml prepare-dataset <name> -i path/to/your/source.csv`.
   The source is certified against `required_columns` (each must be present and
   float-typed); any other columns are dropped. The certified dataset is persisted
   as Parquet under `<state>/datasets/<name>.parquet`.

## Bundled example

`example/orig/example.csv` is a synthetic regression table (columns `x1`, `x2`,
`y`) generated by `scripts/data/make_example_data.py`. It matches the DEFAULT
`required_columns`, so the quickstart works with no configuration. Regenerate it
any time:

```bash
uv run python scripts/data/make_example_data.py
```
